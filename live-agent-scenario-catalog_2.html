Live Agent Improvement · P0 Themes

Live Agent Experience — Scenario Catalog

The end-to-end journey across employee, agent, and organization, with platform ownership and known failure points. Synthesized from the UX Improvements Memo and the Research Memo (217 escalations and support issues).

Scenario catalog

All scenarios per persona, grouped by the five P0 themes. Happy path is the ideal-state flow, Edge is expected variation the system must handle gracefully, Failure is a breakdown observed in the research.

Employee Agent Organization

Employee

Get timely help under the correct identity, in the active language, without repeating information — and always know what happens next.

Access & initiation

Start the right support option with clear steps and only relevant questions.

E1Happy

Describes the need in Slack, Teams, or web; Live Agent is offered only when the request is eligible and the employee, channel, and team are available.

E2Happy

Compares support options — each explains what it provides, which team helps, the expected wait, and what will be shared.

E3Happy

Completes intake with known details pre-filled; asked only for missing information, with review before sharing.

E4Happy

Confirms the handoff and receives clear confirmation that the request is submitted or queued.

E5Edge

Request isn’t eligible (channel, domain, hours, profile) — Live Agent is not offered; an actionable alternative appears instead.

E6Failure

Offered Live Agent for an unsupported request (e.g., HR domain) and reaches a dead end. Configurable Smart Handoff Message

E7Failure

Forced through unnecessary steps or irrelevant questions — e.g., a ticket description required just to open an agent URL. LiveAgent URL handoff · Copilot Backstop

Session reliability, identity & status

Complete one session under the correct identity and always know its status.

E8Happy

Authenticated and linked to the correct account before the session is created.

E9Happy

Sees one persistent status — verifying, queued (position and wait), connecting, connected, ended, failed — throughout.

E10Happy

Ends or exits with clear confirmation; resumes the same session after a retry or device change.

E11Edge

Starts a new chat while one is active — the system returns them to the active session and blocks the duplicate.

E12Edge

Disconnects or goes inactive — notified, then reconnected or closed safely (ghosted-chat recovery).

E13Failure

Account-linking failure blocks the session or connects them as “Guest” under the wrong identity. Marriott — 171 “Guest Guest” chats in 3 days

E14Failure

Conflicting status — “no agent available,” then “you’re in a queue”; or the availability message vanishes into a misleading “session ended” state. Copilot sales handoff

E15Failure

Stuck in a chat and cannot exit — the session stays active for days. User stuck in chat

E16Failure

Handoff times out before the agent connects, prompting retries that create ghost sessions and extra tickets. Premature timeout · ghost chats

Context & content continuity

Continue with an agent without repeating information or losing files and links.

E17Happy

Previews, edits, or removes the summary, history, files, and links before sharing.

E18Happy

Continues without repeating anything — intent, prior troubleshooting, attachments, and links travel with the handoff.

E19Happy

Sees whether each message, file, or link reached the agent, with retry for failures.

E20Edge

Reconnects, reroutes, or transfers — prior context is preserved, never re-entered.

E21Failure

Repeats information already given to the bot; files, links, citations, or handoff actions fail. AWS Connect history · Citations in dev

Language & translation

Get support in the language being used, with automatic detection, routing, and translation.

E22Happy

Writes in any supported language; the active conversation language is detected — not the profile default — and routed or translated automatically.

E23Happy

Experiences the full journey localized: handoff, queue, status, error, fallback, and chat.

E24Happy

Sees when translation is active, can view the original, and failures are clearly surfaced.

E25Edge

Corrects an incorrect language detection with one action.

E26Edge

Uses an unsupported language — offered a supported queue, another language, or a ticket or callback.

E27Failure

Parts of the journey stay in the wrong language — an English waiting message inside a Spanish chat. Brokering strings · Partial translation

Routing & recovery

Reach an available team that matches the issue, profile, and policy.

E28Happy

Routing runs before the request is created — intent, profile, language, hours, eligibility, availability, and capacity all checked.

E29Happy

Sees the destination confirmed: team name, why it was selected, expected wait, next step.

E30Edge

Preferred queue unavailable — offered another team, ticket, callback, or timed retry, with context preserved.

E31Edge

Queue closes mid-wait — the system explains why and converts the active request to the chosen fallback.

E32Failure

Sent to a queue with no available agents because availability was checked globally, not per queue. Queue-specific availability

Agent

Resolve issues quickly — one accurate, well-routed request per employee, with complete context and reliable delivery.

Access & initiation

Receive the right request with enough context to help immediately.

A1Happy

Receives a notification for an actionable request, with intent and handoff label visible.

A2Happy

Validates the queue assignment and routing details; accepts or redirects via the queue directory.

A3Failure

Receives a request with missing required fields or in the wrong queue — investigates from scratch or bounces it.

Session reliability, identity & status

Know the current status of each request; handle one accurate request per employee.

A4Happy

Verifies the request and the employee’s identity; identity warnings surfaced before accepting.

A5Happy

Reviews accurate status, session details, and timestamps; accepts once.

A6Happy

Messages with delivery confirmation in both directions.

A7Happy

Transfers or closes with a status update, transcript, and ticket, so records stay connected.

A8Failure

Wastes time on duplicate or empty ghost sessions that also create tickets. ~80–100 tickets/month at one customer

A9Failure

Cannot identify the employee — sessions arrive as “Guest Guest” or attributed to the bot. Marriott identity issues

A10Failure

Receives the employee’s messages, but replies never reach the employee. Chat interaction issue — High urgency

Context & content continuity

Start with a clear summary and easy access to the full conversation and supporting content.

A11Happy

Starts from a concise issue summary; expands to the full conversation history when needed.

A12Happy

Checks supporting files, links, and source citations delivered with the handoff.

A13Happy

Responds, resolves, or transfers with resolution notes; context preserved for the next team.

A14Failure

Receives only the latest chat instead of the full conversation, or no summary — the employee repeats troubleshooting. AWS Connect · Toyota summary request

A15Failure

Attachments intermittently invisible; KB links render as plain text; agent name or image displays incorrectly. Attachment failures · KB links

Language & translation

Understand the employee’s language and communicate accurately, with or without translation.

A16Happy

Receives requests matched to the detected language via language-based queues.

A17Happy

Reviews the language badge and a bilingual summary before responding.

A18Happy

Responds in the right mode — native or translated — with a confidence indicator in the composer.

A19Edge

Handles a translation failure via a clear error state; the bilingual transcript preserves both versions.

Routing & policy controls

Receive requests that match the queue, skills, and available capacity.

A20Happy

Manages presence and queue availability so routing reflects real capacity.

A21Happy

Sees the routing reason on each assignment — why this request matched this queue.

A22Edge

Flags a misroute; transfers through the directory with preserved context and a resolution code.

A23Failure

Receives requests mismatched to skills or capacity — queue mapping doesn’t reflect the employee’s actual queue.

Organization

Deliver reliable support while managing demand and costs — configurable, testable, measurable operations.

Access & initiation

Control when Live Agent appears, what it says, and what information it collects.

O1Happy

Sets eligibility and intent rules that govern exactly when Live Agent appears.

O2Happy

Configures the handoff — copy, intake form, fallbacks — including how much self-service happens before escalation.

O3Happy

Previews per channel, tests safely, publishes, and monitors handoff analytics.

O4Failure

A configured domain trigger doesn’t surface the expected option; entry points drift from configuration. Custom domain triggers

Session reliability, identity & status

Prevent and quickly diagnose failed, duplicate, stuck, or misidentified sessions.

O5Happy

Defines lifecycle states and identity mapping so both platforms agree on “active,” “ended,” and “failed.”

O6Happy

Sets retry, duplicate-suppression, and timeout policies — including a configurable suppression period.

O7Happy

Tests the end-to-end lifecycle; monitors reliability with alerts and release quality gates (stuck sessions, drop-offs, failed handoffs).

O8Edge

Diagnoses a failed or stuck session by searching shared IDs across both platforms; recovers via safe DLQ replay.

O9Failure

Cannot trace a session across Moveworks and ServiceNow — IDs, states, and lifecycle events aren’t shared. Data API interaction IDs

Context & content continuity

Control what context is shared and confirm it reaches the agent.

O10Happy

Defines required context fields, consent, redaction, and retention policies.

O11Happy

Sets content rules — summary settings, history depth, file security.

O12Happy

Maps payload fields per platform; validates them in a channel test environment before launch.

O13Happy

Monitors delivery logs, alerts on failed transfers, reviews context analytics.

Language & translation

Set up and monitor detection, routing, translation, and fallbacks across channels.

O14Happy

Defines supported languages and automatic detection based on the active conversation.

O15Happy

Maps language skills to queues — e.g., Spanish and Portuguese speakers routed to native-language queues instead of translating. GM language queueing

O16Happy

Sets the translation provider, localized copy, and fallbacks — including dual-language transcripts. Unilever transcripts

O17Happy

Tests per channel; monitors language analytics for detection, routing, and translation quality.

O18Failure

Partially translated experiences reach employees — handoff or waiting strings stay in English — undermining regional rollouts. Partial translation

Routing & policy controls

Control eligibility, routing, priority, capacity, overflow, and fallback rules.

O19Happy

Builds routing policies on issue and employee profile, language, and hours — including VIPs, sensitive topics, alternate desks. JPMC headless routing

O20Happy

Maps queues, availability, capacity, and overflow so offers reflect the employee’s actual queue.

O21Happy

Sets and tests fallbacks in the workflow builder; simulates policies before publishing.

O22Happy

Publishes with versioning and rollback; monitors routing analytics and the audit log.

O23Failure

Multi-ITSM configurations route ticket updates to the wrong ServiceNow instance. Multi-ITSM misrouting

O24Edge

Confirms platform ownership with the ServiceNow AWA team — queues, capacity, transfers, session status, translation fallbacks, rollback.
